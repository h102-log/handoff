# handoff

[![test](https://github.com/h102-log/handoff/actions/workflows/test.yml/badge.svg)](https://github.com/h102-log/handoff/actions/workflows/test.yml)

[English](README.md) | **한국어**

코딩 세션을 안전한 지점에서 멈추고 다음 세션이 읽을 인수인계 작업지시서(Next Action Plan, NAP)를 쓰거나,
새 세션에서 그 문서를 검증하며 작업을 재개하는 Claude Code 스킬입니다. 한국어와 영어 모두 지원합니다.

세션은 git에 없는 것을 압니다 — 왜 그렇게 정했는지, 어떤 접근이 이미 실패했는지, 어떤 주장을 확인하지 않았는지,
다음에 무엇을 하라고 했는지. 컨텍스트가 차거나 하루가 끝나면 새 세션은 이것 없이 시작하고, `/compact` 는 같은
세션 안에 요약으로만 남깁니다. handoff 는 이것을 저장소의 파일로 남기고, 스크립트로 그 파일을 검사하고, 다음
세션이 행동하기 전에 코드와 대조해 확인하게 합니다.

- **작성 모드**: 현재 git 상태를 스냅샷으로 모으고, 이번 세션만 아는 것(결정과 근거, 실패한 접근, 다음 첫 행동)을
  `handoff/yyyy-mm-dd/rN.md` 에 씁니다. 검사 스크립트가 자리표시자·비밀값 유출·작성 후 변경을 잡습니다.
- **재개 모드**: 최신 작업지시서를 읽고, 문서를 쓴 뒤 코드가 바뀌었는지(드리프트)와 문서의 추정을 다시 확인한 다음,
  첫 행동부터의 계획을 보여 주고 승인을 받아 이어 갑니다.

작업지시서의 TL;DR 은 이렇게 생겼습니다(`evals/golden/nap_payhook.md` 발췌):

```markdown
## 0. TL;DR
- 목표: 고정 60초 간격 재시도를 상한(cap)과 full jitter가 있는 지수 백오프로 바꿔, 장애 시 재시도가 한꺼번에 몰리지 않게 한다.
- 현재 위치: 5단계 중 2단계 완료 — 시계 주입(커밋됨)과 `compute_delay` 초안(미커밋). cap부터 시작할 차례.
- ▶ 첫 행동: `src/payhook/backoff.py:4` — `compute_delay`에 상한 적용 (`min(base * 2 ** attempt, max_delay)`) → `PYTHONPATH=src python3 -m unittest discover -s tests`
- 메모: 내일은 cap부터 하고 jitter는 full jitter로 (사용자)
```

## 빠른 시작

Claude Code v2.1.196 이상, git, python3(표준 라이브러리만 씀), `/bin/sh`(Windows는 Git Bash)가 필요합니다.

Claude Code 안에서:

```text
/plugin marketplace add h102-log/handoff
/plugin install handoff@handoff
```

| 명령 | 하는 일 |
|---|---|
| `/handoff:handoff [메모]` | 작업지시서 작성. 메모는 문서에 그대로 남깁니다 |
| `/handoff:handoff lite [메모]` | 경량 작성. 컨텍스트가 거의 찼을 때 콜드리드 검증을 생략합니다 |
| `/handoff:handoff resume [NAP 경로]` | 재개. 경로를 생략하면 최신 작업지시서가 대상입니다 |

작업지시서를 쓰고 `/clear` 한 뒤 새 세션에서 재개합니다(plan 모드 권장). "인수인계 써 줘", "이어서 하자"처럼 말로
요청해도 됩니다.

`/handoff` 로 부르려면 플러그인 대신 개인 스킬로 클론합니다.

```sh
git clone https://github.com/h102-log/handoff.git ~/.claude/skills/handoff
```

한 프로젝트에만 쓰려면 그 프로젝트의 `.claude/skills/handoff` 에 클론합니다. 업데이트는
`git -C ~/.claude/skills/handoff pull` 입니다. 이 문서의 나머지 부분은 명령을 `/handoff` 로 적습니다.

## 언제 쓰나

- **컨텍스트가 부족하지만 같은 세션에서 계속할 때**: `/compact` 로 충분합니다. 아래 실측에서도 같은 세션이 이어 가는
  `/compact` 가 재개 점수가 조금 높았습니다.
- **`/clear` 한 뒤, 다음 날, 또는 다른 사람이 이어받을 때**: `/handoff`. 작업지시서는 저장소의 파일이고, 쓸 때
  스크립트가 검사하고 재개할 때 코드와 대조해 확인합니다.
- **`claude --continue`·`--resume`** 은 이전 대화를 그대로 다시 엽니다. 여유가 남은 대화라면 이걸로 되지만, 옛
  컨텍스트를 그대로 가져오고(거의 찼던 대화는 여전히 거의 찬 상태), 다른 사람은 읽을 수 없습니다.
- **말로 요청한 인수인계 문서**로도 대부분은 됩니다. 아래 실측에서 그런 문서는 문서 6항목 중 5항목을 지켰습니다.
  `/handoff` 는 여기에 `파일:라인`까지 적은 첫 행동, 스크립트 검사(자리표시자·비밀값·상태), 재개 시 드리프트 판정과
  재검증을 더하고, 비용은 더 듭니다.

## 실측 결과

반쯤 진행한 같은 작업을 네 가지 방식으로 새 세션에 넘겼습니다. Opus 5.5 와 Sonnet 5.5 로 방식마다 5라운드씩
Claude Code(`claude -p`, effort xhigh)로 돌렸고, 실행하는 사람의 `CLAUDE.md` 와 사용자 설정(플러그인·훅)은 빼고
돌렸습니다.

1. **문서 없음**: 새 세션이 저장소만 보고 시작
2. **`/compact`** 후 같은 세션에서 계속
3. **말로 요청한 문서**: 말로 요청해 쓴 인수인계 문서를 새 세션이 읽음
4. **`/handoff`** 후 새 세션에서 `/handoff resume`

| 방식 | 문서, Opus | 문서, Sonnet | 재개, Opus | 재개, Sonnet | 비용, Opus | 비용, Sonnet |
|---|---|---|---|---|---|---|
| 1. 문서 없음 | — | — | 3.0 | 3.0 | $0.22 | $0.10 |
| 2. `/compact` | 5.0 | 4.4¹ | **4.6** | **4.8** | $0.68 | $0.29 |
| 3. 말로 요청한 문서 | 5.0 | 5.0 | 4.0 | 4.4 | $0.73 | $0.29 |
| 4. `/handoff` | **6.0** | **6.0** | 4.4 | 4.6 | $0.95 | $0.54 |

문서는 인수인계 문서가 통과한 항목 수(6항목 중), 재개는 재개 세션이 통과한 항목 수(5항목 중)의 5라운드
평균입니다. 비용은 한 실행의 모든 호출에 대해 Claude Code 가 보고한 값입니다.

- **작업지시서는 두 모델 10라운드 모두 6항목을 지켰습니다.** 다른 방식과 갈린 항목은 첫 행동입니다. 2·3번 문서도
  파일 이름과 테스트 명령은 적었지만, 라인 번호까지 적은 것은 20번 중 한 번도 없었습니다. `/handoff` 는 템플릿과
  지시문이 첫 행동에 `파일:라인`과 명령을 요구합니다.
- **확인 안 된 주장을 다시 확인하는지.** 2~4번 문서는 모두 Stripe 주장을 미검증으로 적었지만¹, 그 뒤 실제로 다시
  확인한 횟수는 달랐습니다. `/handoff resume` 은 ⚠️ 항목을 다시 확인하는 단계가 있어 10번 모두 확인했고, 말로
  요청한 문서를 읽은 새 세션은 10번 중 7번이었습니다. 문서 없이 시작한 세션은 그 주장을 알 길이 없어 0번입니다.
  `/compact` 는 같은 세션이 이어 가서 10번 모두 다시 짚었습니다.
- **재개 점수는 `/compact` 가 조금 높았습니다**(Opus 4.6 대 4.4, Sonnet 4.8 대 4.6). 차이는 `max_attempts`
  항목²에서 났습니다. 다만 `/compact` 는 저장소에 아무것도 남기지 않습니다. 요약은 `/clear` 하면 사라지고 다른
  사람이 읽을 수 없습니다.
- **비용.** `/handoff` 가 가장 비쌉니다. 실행당 Opus $0.95, Sonnet $0.54 이고, 2·3번은 Opus $0.68~0.73, Sonnet
  $0.29 입니다. Sonnet 으로 돌린 `/handoff` 는 Opus 로 돌린 `/compact` 보다 싸면서 작업지시서 6항목을 모두
  지켰습니다.

**한계**: 한국어 시나리오 하나, 모델마다 5라운드입니다. 2026-11-02 Windows 에서 Claude Code 2.1.316 으로
쟀습니다. 채점이 키워드라 같은 내용을 다른 말로 쓰면 놓칩니다(¹·²).

## 동작 방식

### 작성 (`/handoff`)

1. **안전한 지점에서 멈춤.** 하던 수정은 코드가 돌아가는 지점까지만 마무리하고, 새 작업은 시작하지 않습니다.
2. **스냅샷.** `scripts/nap.sh` 가 브랜치·HEAD·미커밋 변경과 바뀐 파일마다의 해시를 기록하고, 그 값을 미리 채운
   초안 `handoff/yyyy-mm-dd/rN.md` 를 만듭니다.
3. **정리.** Claude 가 이번 세션만 아는 것 — 결정과 기각한 대안, 막다른 길, 열린 질문, 사용자 메모 — 를 적습니다.
   사실 주장마다 ✅ 확인됨(근거 포함)이나 ⚠️ 추정(재확인 방법 포함)을 붙입니다. 첫 행동은 구체적인 한 단계입니다 —
   `파일:라인`, 거기서 할 일, 실행할 명령.
4. **검사.** 템플릿 자리표시자가 남았거나, 필수 섹션이나 ▶ 첫 행동이 없거나, 비밀값이 옮겨 적혔거나, 스냅샷 뒤에
   작업 트리가 바뀌었으면 스크립트가 문서를 반려합니다. 맥락 의존 표현("아까 그 버그"), 없는 경로, ✅/⚠️ 없는 발견,
   5개가 넘는 읽을 파일, 160행이나 9,000자를 넘는 분량은 경고합니다. 통과하면 작업지시서가 `draft` 에서 `active` 로
   올라갑니다.
5. **콜드리드.** 대화를 본 적 없는 서브에이전트가 작업지시서만 읽고, 첫 행동을 바로 시작하지 못하게 막는 점을
   꼽습니다. Claude 가 그 줄을 고치고, 아는 것으로 답할 수 없는 항목은 지어내지 않고 ⚠️ 로 바꿉니다.
   `/handoff lite` 는 이 단계를 건너뜁니다.

### 재개 (`/handoff resume`)

1. **작업지시서 선택**: 경로를 주지 않으면 현재 브랜치의 최신 활성 작업지시서입니다.
2. **드리프트.** 스크립트가 기록된 브랜치·HEAD·파일 해시를 지금의 저장소와 비교해, 브랜치 이동·새 커밋·히스토리
   재작성·인수인계 이후 바뀐 파일을 보고합니다. Claude 는 계획을 세우기 전에 드리프트를 알리고 확인을 받습니다.
   사용자가 직접 한 작업일 수 있으니 되돌리지 않습니다. 실측 결과의 시나리오에서 진행 중이던 작업이 커밋되고 세션
   밖에서 `handler.py` 가 수정되면 아래처럼 보고합니다. 그대로 커밋만 된 `backoff.py` 는 바뀐 파일로 잡히지
   않습니다.

   ```text
   NAP: handoff/2026-11-03/r1.md — 기록 feat/webhook-retry @ a73cb53 (2026-11-03T10:08+09:00)
   현재: feat/webhook-retry @ 6ad82da
   판정: DRIFT — 새 커밋 1개; 작업 내용 변경 (기록 시점과 파일 내용이 다름)

   [기록 이후 커밋]
   6ad82da wip: backoff draft

   [인수인계 이후 달라진 파일]
     새로 변경   src/payhook/handler.py
   ```

3. **재검증.** ⚠️ 항목을 하나씩 다시 확인해 ✅ 확인·❌ 반증·❔ 여전히 모름으로 나눕니다. 반증된 항목은 계획을
   바꿉니다.
4. **계획 제시 후 대기.** 짧은 요약, 드리프트와 재검증 결과, 첫 행동부터의 실행 계획, 열린 질문을 보여 주고 승인을
   기다립니다. 1~4단계는 읽기만 합니다.
5. **실행.** 첫 수정 전에 작업지시서를 `resumed` 로, 완료 기준을 채우면 `done` 으로 표시합니다. 살아 있는
   작업지시서가 남지 않은 날짜 폴더는 `handoff/archive/` 로 옮겨집니다. 중간에 다시 멈춰야 하면 `/handoff` 가 다음
   작업지시서를 쓰고, 그것이 이 문서를 대체(superseded)합니다.

### 작업지시서 구성

| 섹션 | 내용 |
|---|---|
| frontmatter | 제목·종류·상태·사유, 스크립트가 채우는 기계 필드(created·branch·HEAD·worktree 해시·session·이전 작업지시서) |
| 0. TL;DR | 목표, 멈춘 지점, ▶ 첫 행동, 사용자 메모 |
| 1. 완료 기준 | 검증 명령과 기대 결과 |
| 2. 상태 스냅샷 | 미커밋 변경, 최근 커밋, 마지막 테스트 결과와 확인 시각, 환경(변수 이름만) |
| 3. 이번 세션 진행 | 끝난 것과 진행 중이던 작업이 멈춘 정확한 지점 |
| 4. 결정과 근거 | 결정마다 ✅/⚠️ 근거, 기각한 대안과 이유 |
| 5. 발견·함정 | 근거가 붙은 ✅ 확인된 사실, 재확인 방법이 붙은 ⚠️ 추정 |
| 6. 다음 행동 | ▶ 첫 행동과 그다음 단계들, 단계마다 완료 확인 방법 |
| 7. 하지 말 것 | 이미 실패한 접근과 이유 |
| 8. 열린 질문 | 사용자가 정해야 할 것 |
| 9. 재개 시 읽을 파일 | 우선순위순 최대 5개 |

쓸 내용이 없는 섹션은 지우되 0·1·2·6·9는 항상 남깁니다. 전체 예시:
[evals/golden/nap_payhook.md](evals/golden/nap_payhook.md).

### 저장소에 남기는 것

스킬은 git 상태를 바꾸지 않습니다. 작업지시서 커밋은 사용자 몫이고, 드리프트 판정용 해시 기록 파일(`.rN.files`)만
`.git/info/exclude` 에 등록합니다. 작업지시서는 커밋되어 공유되므로 비밀값은 변수 이름만 적고, 검사 스크립트가
토큰·키 형태의 값과, 저장소 루트의 `.env*`·두 단계 아래 폴더까지의 `config*.json` 에 든 비밀값이 문서에 옮겨
적혔는지 확인합니다.

## 작업지시서를 커밋하지 않으려면

작업지시서는 다른 사람도 읽도록 커밋하는 것이 기본입니다. 저장소에 남기지 않으려면 `handoff/` 를 `.gitignore`(모두에게
적용)나 `.git/info/exclude`(나에게만 적용)에 넣습니다. 작성·검사·드리프트 판정은 똑같이 동작합니다.

## 제거

- 플러그인: `claude plugin uninstall handoff@handoff` 후 `claude plugin marketplace remove handoff`
- 직접 클론: `~/.claude/skills/handoff`(또는 프로젝트의 `.claude/skills/handoff`)를 지웁니다
- 쓰던 저장소마다 작업지시서가 든 `handoff/` 폴더와, 스킬이 `.git/info/exclude` 에 추가한 `/handoff/**/.*.files`
  한 줄이 남습니다. 필요 없으면 지웁니다.

## 언어

작업지시서 본문과 Claude 의 답변은 사용자가 쓰는 언어를 따릅니다. 템플릿은 한국어 `assets/nap-template.ko.md` 와
영어 `assets/nap-template.en.md` 두 가지이고, 한국어·영어 외의 언어로 요청하면 영어 템플릿의 섹션 제목을 그대로
두고 본문을 그 언어로 씁니다. 검사 명령은 어느 템플릿으로 쓴 작업지시서든 받아들입니다. 명령만 입력했을 때(예:
`/clear` 직후 `/handoff resume`)는 이어받을 작업지시서의 언어를 씁니다.

스크립트 메시지의 언어는 `--lang ko|en` 옵션(스킬이 넘김), 환경 변수 `HANDOFF_LANG`, 시스템 로캘(한국어 로캘이면
`ko`, 그 밖에는 `en`) 순서로 정해집니다.
스킬을 불러올 때 자동으로 수집하는 스냅샷에는 `--lang` 이 붙지 않으므로, 로캘과 상관없이 그 언어를 정하려면
`~/.claude/settings.json` 에 `"env": { "HANDOFF_LANG": "ko" }` 를 넣습니다(영어는 `"en"`).

비교하고, 라운드마다 모델을 10번 부릅니다(호출마다 $5 상한). 4번 방식의 픽스처 저장소에는 이 저장소 판을 프로젝트
스킬로 설치하고, 실행하는 사람의 `CLAUDE.md` 와 사용자 설정(플러그인·훅)은 읽지 않습니다. 위의 5라운드 실행은

```sh
bash evals/run_4way_ab_test.sh <결과 폴더> <라운드 수>

```
